# 🦉 Wootify (#WBOTS) - торговые боты для WOOFi Pro

Wootify - самостоятельно разворачиваемое приложение для автоматической торговли бессрочными фьючерсами
на [WOOFi Pro](https://dex.woo.org) (Orderly Network). Проект начат командой Java Boys на конкурсе
WOOFi ✖ DeFrens ✖ GoMining Trading-Bot Competition (2025).

## Возможности

- **Торговые боты как потоки на бэкенде.** У каждого бота свой поток, жизненный цикл, настройки, циклы, ордера и журнал.
- **Управление из UI.** Создание, настройка, запуск и остановка ботов; живые статусы, пульс, текущее занятие, результат.
- **Переживают перезапуск.** Если сервер остановлен или упал, при следующем старте все боты, которые должны работать, продолжают с того же места без дублей ордеров.
- **Видимые ошибки.** Статус «Сбой» или «Ожидает перезапуска», последняя ошибка, журнал событий со стеком исключения.
- **Автоматические перезапуски** после сбоев с нарастающей паузой; временные сбои (сеть, биржа, нет цен) не останавливают бота.
- **Стратегия усреднения (DCA):** базовый ордер, сетка страховочных ордеров, фиксация прибыли от средней цены, стоп-лосс, учёт PnL с комиссиями.
- **Бумажная торговля** на живых ценах Orderly: без ключей и без риска.
- **Реальная торговля** через `woofipro-bridge` (основная или тестовая сеть Orderly).
- Ручной торговый терминал (прототип времён хакатона).

## Стек

Java 21, Spring Boot, Jmix 2.6 (Vaadin), PostgreSQL, Liquibase; мост к бирже - Python (FastAPI + CCXT).

## Быстрый старт

### Локально

Нужны JDK 21 и PostgreSQL.

```bash
createdb wootify                       # пользователь и пароль по умолчанию: pgadmin / pgadmin
MAIN_DATASOURCE_URL=jdbc:postgresql://localhost:5432/wootify ./gradlew bootRun
```

Откройте http://localhost:8080, вход `admin` / `admin`.

Без доступа к Orderly можно запустить на синтетических ценах: `WOOTIFY_MARKET_DATA=synthetic`.

### Docker Compose

```bash
cp .env.example .env      # задайте пароли и ключ шифрования: openssl rand -base64 32
docker compose up --build
```

UI будет доступен на порту `WOOTIFY_PORT` (по умолчанию 8088). Наружу публикуется только UI;
PostgreSQL доступен лишь с локальной машины, pgAdmin запускается отдельно: `docker compose --profile tools up -d pgadmin`.

## Работа с ботами

1. **Инструменты** (Settings → Symbols): добавьте инструмент, например `ETH-PERP` с тикером Orderly
   `PERP_ETH_USDC` и тикером CCXT `ETH/USDC:USDC`.
2. **Бот** (Боты → Создать): название, инструмент, режим (бумажная или реальная торговля), сеть и параметры DCA.
   Под параметрами показывается предпросмотр сетки: стоимость каждого ордера и его отступ от базовой цены.
3. **Запуск:** кнопка «Старт» в списке или «Запустить» в карточке. Некорректные настройки (например, депозит
   слишком мал для минимальной стоимости ордера на бирже) отклоняются с понятной причиной.
4. **Наблюдение:** в списке статус, пульс, текущее занятие и результат; в карточке - вкладки «Состояние»,
   «Циклы», «Ордера», «Журнал». Страницы обновляются автоматически.
5. **Остановка** с выбором действия:

| Действие | Что происходит |
|---|---|
| Оставить ордера и позицию | Бот перестаёт работать, всё остаётся на бирже |
| Отменить ордера, оставить позицию | Ордера отменяются; при следующем запуске бот восстановит сетку и продолжит цикл |
| Отменить ордера и закрыть позицию | Ордера отменяются, позиция закрывается рыночным ордером, цикл закрывается |

Настройки работающего бота изменить нельзя: сначала остановите его. Изменения применяются при следующем запуске,
а уже открытый цикл доводится по параметрам, с которыми он был открыт.

### Статусы

| Статус | Значение |
|---|---|
| Остановлен | Бот не работает |
| Запускается / Останавливается | Переходное состояние |
| Работает | Поток бота выполняет такты. Если пульса нет дольше обычного, в списке появляется «нет пульса» |
| Приостановлен | Сервер был штатно остановлен; бот продолжит работу при следующем старте |
| Ожидает перезапуска | Бот упал и будет перезапущен после паузы |
| Сбой | Ошибка конфигурации или исчерпаны попытки перезапуска; причина - в «Последней ошибке» и журнале |

### Что происходит при сбоях

- **Временный сбой** (биржа или мост недоступны, нет свежих цен): предупреждение в журнале, такт повторяется.
  Если сбои не проходят 15 минут, это считается падением.
- **Падение** (неожиданное исключение): бот перезапускается через 10 с, 20 с, 40 с… (не более заданного числа раз),
  затем переходит в «Сбой». Ручной запуск сбрасывает счётчик.
- **Штатная остановка сервера:** боты приостанавливаются и продолжают работу после старта.
- **Аварийное падение сервера:** при старте тот же экземпляр сразу забирает своих ботов; если ботов подхватывает
  другой экземпляр, он ждёт истечения аренды (30 с).
- **Потерянный ответ биржи:** каждый ордер сначала записывается в БД с уникальным `clientOrderId`, поэтому после сбоя
  бот находит его на бирже или безопасно отправляет повторно.

Подробное устройство движка: [docs/BOT_ENGINE.md](docs/BOT_ENGINE.md).

## Реальная торговля

1. Запустите `woofipro-bridge` (в Docker Compose он поднимается автоматически).
2. Создайте аккаунт (Settings → Accounts) с идентификатором аккаунта Orderly и ключ API (Settings → Api Keys):
   ключ, секрет, `env` = `mainnet` или `testnet`, `brokerId` = `woofi_pro`. Секрет хранится в БД зашифрованным.
3. В боте выберите режим «Реальная торговля», сеть, совпадающую с ключом, аккаунт и ключ.

Начинайте с тестовой сети и небольших сумм. Используйте ключи Orderly только с правом торговли.

## Конфигурация

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `MAIN_DATASOURCE_URL`, `PG_*` | Подключение к PostgreSQL | `localhost:25438/wootify` |
| `WOOFI_BRIDGE_BASE_URL`, `WOOFI_BRIDGE_API_KEY` | Адрес и общий секрет моста | `http://localhost:8081`, `woofipro` |
| `WOOTIFY_ENCRYPTION_KEY` | Ключ шифрования секретов API (base64, 32 байта); обязателен в профиле `prod` | не задан |
| `WOOTIFY_ADMIN_PASSWORD` | Пароль пользователя `admin`, применяется при старте | не задан |
| `WOOTIFY_INSTANCE_ID` | Стабильный идентификатор экземпляра - владельца ботов | имя хоста |
| `WOOTIFY_MARKET_DATA` | Источник цен: `orderly` или `synthetic` | `orderly` |

Тонкие настройки движка - свойства `wootify.bots.*` (см. `BotEngineProperties`).

## Разработка

```bash
./gradlew test                                   # нужен PostgreSQL с базой wootify_test (TEST_DB_URL)
ORDERLY_LIVE_TESTS=true ./gradlew test --tests '*LiveTest'   # проверка живого API Orderly
```

Тесты покрывают расчёты DCA, симулятор биржи, жизненный цикл ботов (запуск, остановка, сбои, перезапуски
сервера, конкурирующие экземпляры), полные циклы стратегии и экраны. CI - GitHub Actions (`.github/workflows/ci.yml`).

Документы: [дорожная карта](docs/ROADMAP.md), [движок ботов](docs/BOT_ENGINE.md), [мост](woofipro-bridge/README.md).
